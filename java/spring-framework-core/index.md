## 1. IoC 与依赖注入

Spring 容器负责创建 Bean、解析依赖并管理生命周期。构造器注入能够表达必需依赖、支持不可变字段，也更容易在不启动容器时测试。组件扫描方便但会隐藏模块边界；大型项目可用明确配置类组织依赖。

Bean 默认是单例作用域，意味着同一实例会服务多个请求。单例 Bean 不应在字段中保存请求级可变状态。

## 2. Bean 生命周期

容器读取 Bean 定义，实例化对象，注入依赖，执行各类后置处理和初始化回调，关闭时执行销毁回调。许多框架能力——配置属性、事务、异步、缓存——都依赖 BeanPostProcessor 创建或包装对象。

构造阶段不要访问尚未完成代理的能力。初始化逻辑应快速且可失败；长时间预热需要可观测、可取消，并与应用就绪状态协调。

## 3. AOP 与代理边界

Spring AOP 通常通过代理拦截方法调用。外部对象通过代理调用时，事务、缓存或重试增强才有机会执行；同一个对象内部 `this.method()` 绕过代理，是很多“注解不生效”的根源。

切面适合日志、事务、权限等横切关注点，不应隐藏关键业务流程。切点范围必须精确，避免一次规则意外代理整个包。

## 4. Spring MVC

DispatcherServlet 负责请求分发，HandlerMapping 找控制器，参数解析器构造参数，消息转换器处理 JSON，异常解析器生成错误响应。控制器应保持薄：完成协议转换和校验，把业务交给应用服务。

全局异常处理统一错误协议；拦截器适合请求上下文和授权前置检查；Filter 更靠近 Servlet 边界。三者职责不能混用。

## 5. 声明式事务

`@Transactional` 定义事务边界，但要理解传播、隔离、只读提示、回滚规则和代理限制。常见失效原因包括自调用、对象未被容器管理、方法不可代理、异常被吞掉，以及使用了错误事务管理器。

事务方法应短小，不在数据库事务中等待外部 HTTP。跨数据库或跨服务的一致性不能依靠本地事务注解解决。

## 6. 缓存、任务与事件

缓存要同时定义键、过期、穿透、击穿、更新和故障策略。`@Cacheable` 简化调用，但不能替代缓存一致性设计。

异步任务必须指定独立执行器、队列和异常处理。定时任务在多实例环境中可能重复执行，需要幂等或分布式调度。应用事件适合同进程解耦，但不能作为可靠消息队列；事务回滚和进程崩溃时事件可能丢失。

## 7. WebClient 与响应式编程

WebFlux 适合端到端非阻塞、连接数量高的场景。响应式线程中执行 JDBC 或其他阻塞调用会破坏扩展性。普通 CRUD 服务使用 Spring MVC 加虚拟线程或受控线程池通常更易维护，选择应由负载测试决定。

## 8. 测试策略

- 纯单元测试：直接构造业务对象，不启动 Spring。
- Slice 测试：只加载 MVC、JPA 等特定层。
- 集成测试：验证真实配置、数据库和消息组件。
- 契约测试：验证服务之间的协议兼容。

不要把所有测试都写成完整容器启动测试，否则速度慢且故障定位困难。
