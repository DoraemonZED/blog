1. 流、文件与字符编码

字节流处理二进制，字符 Reader/Writer 处理文本。文本读写必须明确字符集，通常使用 UTF-8；依赖操作系统默认编码会导致跨环境乱码。所有文件、Socket 和流都应通过 try-with-resources 关闭。

Path path = Path.of("config.json");
String content = Files.readString(path, StandardCharsets.UTF_8);
Files.writeString(path, content, StandardCharsets.UTF_8,
    StandardOpenOption.CREATE, StandardOpenOption.TRUNCATE_EXISTING);

处理大文件不要一次读入内存。使用缓冲流、逐行处理或 Channel，并对上传文件限制尺寸、扩展名、真实内容类型和目标路径。

2. NIO 核心模型

Buffer 保存读写位置，Channel 表示数据通道，Selector 让单线程管理多个非阻塞通道。Buffer 写入后读取前通常需要 flip()；读取结束准备再次写入时使用 clear() 或 compact()。许多 NIO 错误来自状态切换不清晰。

非阻塞 IO 适合连接多、单次工作较小的场景，但状态机复杂。普通业务服务不应仅为了“性能”手写 Selector，成熟框架通常更可靠。

3. Socket 设计

网络是不可靠边界。客户端和服务端都必须设置连接、读取、写入和整体请求超时；协议需要消息边界、最大长度、版本和错误码。TCP 提供字节流而不是消息，单次 read 不保证得到一个完整业务包。

重试只适合可安全重复的操作。写请求应设计幂等键，并使用指数退避和随机抖动，防止故障时所有客户端同时重试。

4. HTTP 与 TLS

HTTP 客户端应复用连接，限制最大连接数，并区分连接超时和响应超时。处理状态码时不能只把 200 当成功：重定向、缓存、条件请求、限流和服务端错误都有明确语义。

TLS 提供传输机密性和身份验证。不要关闭证书校验解决测试问题；应建立正确的信任链、主机名验证和证书轮换机制。敏感服务还可评估双向 TLS。

5. 序列化

跨服务协议应明确 schema 和兼容策略。JSON 易读、生态广；Protocol Buffers 等二进制协议更紧凑并具有字段约束。不要对不可信输入使用 Java 原生对象反序列化。任何反序列化入口都应限制类型、深度、字段长度和总体大小。

6. Netty 与事件循环

Netty 将连接事件交给 EventLoop。事件循环线程中不能执行长时间阻塞任务，否则同一线程负责的其他连接都会延迟。耗时计算或阻塞调用应转移到受控执行器，同时保留背压和顺序要求。

常见问题包括 ByteBuf 引用计数泄漏、Handler 线程安全、粘包拆包、无界写缓冲和连接空闲检测。上线前应监控连接数、待发送字节、事件循环延迟和内存分配。

7. WebSocket、HTTP/2 与 HTTP/3

WebSocket 适合双向长连接，需要心跳、重连、身份续期和慢消费者处理。HTTP/2 在单连接上复用流，但仍可能受连接级别拥塞影响。HTTP/3 基于 QUIC，部署时还要考虑 UDP 可达性和网关支持。协议升级应由真实流量测试驱动。

检查表

  • 字符编码是否明确？
  • 输入大小是否受限？
  • 是否设置全部超时？
  • 是否存在无界缓冲？
  • 重试是否幂等并带退避？
  • TLS 校验是否完整？
  • 阻塞任务是否占用事件循环？
