## 1. 一次请求如何到达业务代码

客户端建立连接并发送 HTTP 请求，网关或反向代理完成 TLS、路由和基础限制，Servlet 容器解析请求，再依次执行 Filter、Servlet/控制器和响应写出。理解这条链路，才能正确放置鉴权、日志、跨域、异常处理和压缩逻辑。

HTTP 是无状态协议。Cookie 由浏览器保存并随请求发送，Session 通常在服务端保存会话状态。分布式部署时，Session 需要共享存储或粘性路由；更常见的 API 方案是短期访问凭证配合安全的刷新机制。

## 2. Servlet、Filter 与 Listener

Servlet 处理请求，Filter 适合横切的请求/响应加工，Listener 观察应用和会话生命周期。它们通常被多线程并发调用，实例字段不能保存某次请求的可变数据。

Filter 顺序非常重要：请求 ID、访问日志、认证、授权、业务处理和异常记录要形成清晰链路。读取请求体进行日志记录时要限制大小并脱敏，不能让调试功能泄露密码和 Token。

## 3. REST API 设计

资源路径使用名词，HTTP 方法表达操作，状态码表达结果。创建接口考虑幂等键；更新接口区分整体替换与局部修改；列表接口提供稳定排序、分页和上限。

错误响应应有稳定机器码、用户可读消息和追踪 ID：

```json
{
  "code": "ORDER_NOT_FOUND",
  "message": "订单不存在",
  "traceId": "01J..."
}
```

不要把堆栈、SQL 或内部主机名返回客户端。API 版本优先通过兼容演进解决，确需破坏性修改时再引入明确版本。

## 4. 参数校验与错误边界

输入校验分三层：结构校验确保格式正确，领域校验确保业务规则成立，数据库约束提供最后防线。校验失败返回具体字段，但授权失败时避免泄露资源是否存在。

全局异常处理应把领域异常映射到稳定状态码，同时保留服务端原始异常链供诊断。切勿把所有异常都返回 200，也不要把所有客户端错误都返回 500。

## 5. 上传、下载与实时通信

文件上传要限制请求体、文件数、单文件大小和处理时间；文件名不能直接拼接到服务器路径。必要时做病毒扫描、内容类型检测和隔离存储。下载接口要防路径穿越，并正确设置缓存和内容处置响应头。

SSE 适合服务端单向事件流；WebSocket 适合双向实时通信。两者都需要连接鉴权、心跳、慢消费者处理、重连和部署层超时配置。

## 6. Web 安全基线

- XSS：输出编码并限制危险 HTML。
- CSRF：基于 Cookie 的认证要使用 SameSite、CSRF Token 等防护。
- CORS：只允许确切来源、方法和请求头，不能随意组合通配来源与凭证。
- 会话：Cookie 使用 Secure、HttpOnly 和合理 SameSite。
- 权限：服务端逐资源校验，不依赖前端隐藏按钮。
- 限流：按用户、IP、接口和业务对象组合设计。

## 7. 可观测与测试

记录请求 ID、路由模板、状态码和耗时，不把完整 URL 参数作为无限基数指标。测试至少包括控制器契约、校验失败、权限边界、异常映射、文件限制和超时行为。
